# 09 里程碑与验收

本文档是执行的主干:M0–M8 九个里程碑,每个任务附字面验收标准。验收标准是契约:执行 agent 不得修改、不得放宽、不得以"能跑通/无报错"替代。

## 执行协议(每个里程碑都适用)

1. 一个里程碑 = 一个分支 + 一个 PR + 一次(或一组)agent 运行。开工前必读:`README.md` 锁定决策、本里程碑任务表全文、里程碑标注的必读文档(见 `README.md` 目录表)。
2. 收尾报告四项,缺一不可:
   - 逐条引用本文档中任务验收标准的**原文**打勾;
   - 每条附可验证证据(命令输出的决定性一行、文件路径与行号、截图或录屏路径);
   - 缺口清单:未做、部分做、有偏差的条目及原因;没有缺口也要写"缺口:无";
   - 所有"完成"结论必须来自实际运行过的命令输出,未运行过的标注"未核实"。
3. 数值平衡窗口:标注"初始值"的数值可在 ±50% 内调整,记录于 PR 描述;验收标准中的阈值(如"≤5%""≥300")不属于平衡窗口,不得调整。
4. 实现成本远超预期时:停下,在 PR 中说明代价与备选,等待计划所有者决定。禁止自行简化(硬编码、跳过分支、砍边界条件)。
5. 里程碑标注的变异验证任务:人为改坏目标逻辑 → 确认对应测试变红 → 还原 → 确认变绿,三步的命令输出摘录进收尾报告。
6. 阶段性接口(如 M1 的临时配方表)在本文档中显式标注,替换时机固定;这不属于降级。

## 里程碑依赖

串行执行:M0 → M1 → M2 → M3 → M4 → M5 → M6 → M7 → M8。唯一允许的并行:M3 的人工抽审等待期内可以开工 M4 前三项任务(M4-T1/T2/T3 不依赖配方数据)。
