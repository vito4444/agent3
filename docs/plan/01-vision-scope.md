# 01 愿景与范围

## 一句话定位

在一颗陌生星球上从徒手求生起步,把双手换成机器、把基地连成生产链、把火箭送上天,在一个活着的星系里与三个性格迥异的 AI 势力贸易、对峙、抢夺地盘——一款 Timberborn 视角与画风基准的俯视角星际生存建造游戏,单机,发行到 Steam。

## 体验基准(参考对象与取舍)

| 参考 | 取什么 | 明确不取什么 |
|---|---|---|
| Timberborn | 俯视角可旋转相机、微缩模型般的可读画面、网格化建造、殖民者搬运劳动的烟火气 | 流体物理模拟、木质美术主题、动物角色 |
| Factorio / Dyson Sphere Program | 生产链的深度与"手工到自动化"的爽感、配方体系的严谨 | 传送带铺设玩法(首发版)、万台机器的巨型工厂尺度 |
| RimWorld | 殖民者需求与小规模灾难带来的叙事感 | 深度角色关系与心情系统、随机叙事 AI |
| 4X 游戏(如群星) | 星系尺度的势力疆域、贸易与占领 | 全模拟的 AI 帝国、舰队战、外交树 |

## 设计支柱(所有取舍以此为准)

1. **从手到机器**:玩家早期做过的每一种手工动作,中期都有一台机器接管它。这个映射是显式的、一比一的(映射表见 `03-base-building-and-economy.md`),玩家能清晰感到"我把自己自动化了"。
2. **配方讲得通**:资源丰富、配方组合爆炸(目标 320–420 条),但每一条都有现实逻辑支撑,附一句自动生成的合理性文案。玩家在配方浏览器里看到的不是随机拼贴,而是一套自洽的工业体系。
3. **一镜到星系**:四层缩放——第一层看得清基地里每个殖民者,第二层看全区域远景,第三层看所在的星球,第四层看所处的星系。信息随层级重组,操作在每一层都有意义。
4. **活的对手,便宜的模拟**:AI 势力用实力值标量 + 规则扩张跑在后台,玩家抵达才实例化成真实基地。三种性格产生真实可观测的行为差异;占领它们的收益是具体的资源与科技,不是数值贴纸。
5. **范围纪律**:这个类型死于范围失控。不做清单是契约,添加任何范围外内容需要计划所有者批准并同时移除等量内容("范围守恒")。

## 平台与商业形态

- 平台:PC,Steam 发行。Windows x64 必须,Linux x64 必须(同时服务 Steam Deck 的 Proton 路径)。
- 单人单机,离线可玩,无账号体系,无内购,无 DLC 规划(首发版)。
- 目标配置见 `08-architecture.md` 性能预算节。
- 定价与发售日期为用户决策项(见 `10-steam-release.md`)。

## 游戏流程弧线(五幕)

1. **坠落(T0)**:逃生舱坠毁在尘壤星。4 名幸存者,手镐、手工台、篝火炉。挖冰化水、电解产氧、种藻果腹,熬过夜寒与沙暴。教学脚本覆盖本幕。
2. **通电(T1)**:太阳板与风机立起来,采矿机、熔炉、装配机逐台接管手工动作,搬运蛛跑起来。基地从"营地"变成"工厂雏形"。
3. **化工与链条(T2)**:电解、蒸馏、化合、聚合上线,生产链纵深拉开;无人机港解决区域物流;人口增长,士气系统开始要求配套。
4. **上天(T3)**:火箭部件链(箭体、引擎、贮箱、导航舱)与燃料链(Sabatier 甲烷或液氢液氧)建成,第一枚火箭把前哨包送上苍卫。通讯阵列点亮星系,三个 AI 势力浮出水面。
5. **星系博弈(T4)**:多基地运营,跨星物流航线,与商盟做买卖,和赤旗军团在边境星体对峙,窥探静默会的高墙。走向三种结局之一。

## 胜负条件

胜利(达成任一,达成后可继续沙盒游玩):

1. **星系霸权**:控制曦光系 12 个星体中的至少 8 个(自有或附庸)。
2. **跃迁灯塔**:建成终局巨构"跃迁灯塔"。其配方要求至少 2 种非出生星独有资源(超导蓝矿、重氢冰、铂族砂中任二),确保玩家必须通过贸易、殖民或占领与星系发生深度互动,单星龟缩无法达成。

失败:所有基地的殖民者数量归零,且没有任何在途殖民舱。触发失败结算画面与读档入口。

## 明确不做清单(契约)

以下内容首发版不做。每条附理由与替代方案。执行 agent 不得实现列表中的任何一项。

| 不做 | 理由 | 替代 |
|---|---|---|
| 多人联机 | 用户明确排除;此类型范围失控的头号来源 | 无。单机确定性模拟因此得以简化 |
| 传送带物流 | 可视化物件流的实现与性能成本极高 | 搬运蛛 + 无人机港,见 `03` |
| 流体/气体体积模拟(Timberborn 水、ONI 气体) | 模拟与关卡成本巨大,非本作支柱 | 电力式抽象网络:氧气与液体走产量/消耗结算,见 `03` |
| 逐房间气压与温度 | 同上 | 建筑级保温与全基地氧气网络 |
| 全球面自由建造的星球表面 | 球面网格建造是独立的大型技术课题 | 星体 = 若干块矩形登陆区域,行星层选区进入,见 `02` |
| N 体轨道力学 | 玩法收益低 | 固定圆轨道,转移时间查表,见 `06` |
| 多星系/银河尺度 | 范围守恒 | 一个精心设计的星系,12 个星体 |
| AI 势力之间互相开战 | 模拟与可读性成本高 | 势力只争夺中立星体、只与玩家冲突,见 `07` |
| RTS 微操战斗 | 战斗不是支柱 | 轻量自动战斗,三类驻守指令,见 `07` |
| Mod / 创意工坊 | 首发范围外 | 数据驱动架构为未来 Mod 留了结构,但不做加载器与文档 |
| 随机叙事事件系统 | 范围守恒 | 固定灾害表 + 少量脚本事件(救援、最后一人) |
| 载具手动驾驶 | 非支柱 | 所有载具为调度式 |
| 主机版 / VR | 首发范围外 | 无 |
| Steam Deck 官方 Verified 承诺 | 全套手柄 UI 成本高 | 键鼠优先;Deck 以"能跑"为目标,不承诺认证,见 `10` |

**范围守恒规则**:开发中任何人(包括执行 agent)提出的新增内容,必须经计划所有者批准,且批准时同步指定从计划中移除的等量内容。没有例外通道。

## 顶级风险与对策

| 风险 | 对策(落在计划何处) |
|---|---|
| 配方数百条导致玩家淹没、内容失控 | 层级门控(每科技节点解锁 ≤14 条)、配方浏览器三击可达、图标语法自动合成、随机抽审门(`04`) |
| 多区域多星体模拟拖垮性能 | 活跃区域全模拟 + 非活跃抽象刻,偏差 ≤5% 验收(`06`);性能预算表与基准场景(`08`) |
| AI 势力"假"感、懒实例化穿帮 | 确定性布局种子(重访一致)、破坏差分持久化、情报报告引用真实沙盘数字(`07`) |
| 美术量失控 | 灰盒先行(所有功能验收不依赖美术)、图标自动合成、模块化建筑套件、功能色系(`05`) |
| 引擎版本漂移 | 锁 Unity 6.3 LTS,升级只在里程碑边界、只升补丁号(`08`) |
| 交付缩水 | 每个任务字面验收标准 + 收尾四项报告协议(`09` 执行协议) |
