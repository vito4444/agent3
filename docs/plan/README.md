# 《星壤》(Starsoil) 开发计划总览

> 工作名《星壤》/ Starsoil 为占位名称,发行前需完成商标与重名查验(见 `10-steam-release.md` 的用户动作清单)。

这是一个可发行到 Steam 的单机游戏的完整开发计划:俯视角星际生存建造游戏,视角与画面基准参考 Timberborn。玩家从一颗星球上的坠毁点开始,手工采集、手工合成、活下去;随后建造机器替代双手、搭建生产链;最终建造火箭前往同星系的其他星球殖民,与三个 AI 势力贸易、竞争与抢夺地盘。

本计划由多份文档构成,面向"由 AI agent 分里程碑执行"的工作方式编写:所有系统给出结构、规则与初始数值,所有里程碑任务附带字面验收标准。

## 锁定决策(执行 agent 不得重新讨论)

以下决策已定,执行时照做。变更需回到计划所有者(用户)确认后修订本计划,再执行。

1. 引擎与版本:Unity 6.3 LTS(6000.3 系列,取当前最新补丁),URP 渲染管线。版本升级只允许发生在里程碑边界,且只升补丁号。
2. 呈现:3D 低多边形风格化,俯视角可旋转相机,网格化建造。参考 Timberborn 的取景与可读性,不复制其内容与玩法资产;Timberborn 标志性的流体物理模拟明确不做。
3. 范围:单人单机;一个星系(曦光系,12 个可殖民星体);无多人联机;无创意工坊与 Mod 支持(首发版)。完整清单见 `01-vision-scope.md`。
4. 物流形态:搬运机器人与无人机,不做传送带(首发版)。理由与替代方案见 `03-base-building-and-economy.md`。
5. 模拟架构:纯 C# 模拟核心(不依赖 UnityEngine),固定步长 tick,单机确定性;表现层与模拟层分离。见 `08-architecture.md`。
6. 配方内容:由仓库内工具 `RecipeGen` 从"材料 × 工艺 × 形态"矩阵加人工维护的有效性掩码生成,目标 320–420 条,每条附自动合成的合理性文案,8 项校验全过才算内容合格。见 `04-recipes-items-tech.md`。
7. AI 势力:实力值标量模型 + 邻接扩张规则 + 玩家抵达时懒实例化;三种性格(贸易型/扩张型/封闭型)行为差异以可测断言定义;AI 势力之间不互相开战(首发版)。见 `07-factions-combat-occupation.md`。
8. 占领收益:被占星体的独有资源矿脉可采 + 该势力两条封锁科技分支二选一(选剩的永久失去),不是数值加成。见 `07-factions-combat-occupation.md`。
9. UI 技术:UI Toolkit;本地化 zh-CN(源语言)+ en,使用 Unity Localization 包,所有字符串走键值表。
10. 存档:JSON + gzip 分块,带 schema 版本与迁移注册表。二进制化只在实测主线程停顿超过 200ms 时触发。

## 基于用户需求做出的假设

计划所有者(用户)给出了核心需求并授权细节由计划决定。以下是计划自行敲定、用户未逐条确认的假设;如与预期不符,修订对应文档后再开工。

- 平台:Windows x64 + Linux x64(Steam Deck 以 Proton 兼容为目标,不做官方"Verified"承诺,见不做清单)。
- 语言:界面中文简体 + 英文双语首发。
- 战斗形态:轻量自动战斗(单位只接受驻守/巡逻/集结三类指令),不做 RTS 微操。
- 星系为固定拓扑 + 种子化随机资源分布:12 个星体的身份、势力归属、独有资源固定;矿脉位置、地形、数值按种子生成。
- 定价、正式名称、发售与 Next Fest 时间点、音乐外包预算为用户决策项,计划中标注位置但不代作决定。

## 用本计划驱动执行 agent 的方法

1. 每个里程碑(M0–M8)开一个分支、一个 PR、一次(或一组)agent 运行。
2. 给执行 agent 的任务指令必须包含:本 README 的"锁定决策"、`09-milestones.md` 中该里程碑的任务表原文、该里程碑标注的必读文档清单。
3. 要求执行 agent 在收尾报告中:逐条引用任务验收标准原文打勾;每条附可验证证据(命令输出的决定性行、文件路径与行号、截图);显式列出缺口清单,没有缺口也要写"缺口:无"。
4. 数值平衡窗口:文档中标注"初始值"的数值允许在 ±50% 内调整,调整必须记录在该里程碑 PR 描述中;结构、系统间联动、验收标准本身不得修改。
5. 禁止事项:不得增加范围(新系统、新平台、新玩法);不得更换技术栈;不得因实现成本高而静默简化——遇到成本远超预期的任务,停下来向计划所有者说明代价并等待决定。

## 与用户既有项目的隔离声明

本计划从零构建,未读取、未引用、未借鉴用户任何既有项目的内容与代码。对外部作品(Timberborn、Factorio、Dyson Sphere Program、RimWorld 等)仅以公开可见的玩法与呈现作为体验基准,不使用其任何资产与文本。

## 术语表

| 术语 | 含义 |
|---|---|
| tick | 模拟的最小时间步。1 游戏日 = 12000 tick,1 游戏时 = 500 tick |
| 星图刻 | 势力沙盘的结算步,每 1 游戏时结算一次 |
| 区域(Region) | 一个星体上的一块可建造网格地图(128/192/256 见方),基地的载体 |
| 活跃区域 | 玩家相机所在、跑全量模拟的区域;其余区域跑抽象刻 |
| 抽象刻 | 非活跃区域每游戏时一次的公式化产出结算,见 `06-space-and-logistics.md` |
| 懒实例化 | AI 势力星体平时只有摘要数据,玩家抵达时才生成具体基地,见 `07-factions-combat-occupation.md` |
| 独有资源 | 只在特定星体存在的原料,共 8 种,见 `02-world-and-survival.md` |
| 封锁科技分支 | 玩家无法自研、只能通过占领获取的势力科技树,共 6 条,见 `07-factions-combat-occupation.md` |
| 数据核 | 研究消耗品,5 阶,对应 Factorio 科学包的定位,见 `04-recipes-items-tech.md` |
| T0–T4 | 科技层级:T0 徒手求生、T1 通电、T2 化工、T3 高技术、T4 航天与终局 |
